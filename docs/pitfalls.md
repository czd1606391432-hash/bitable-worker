# 飞书多维表格接口踩坑记录

下面每一条都是在真实租户里实际遇到过的。飞书的接口会更新，遇到和这里不一致的情况，以官方文档和实测为准。

## 权限

**应用默认看不到任何已有的表格。** 报 `91403` 基本都是这个原因。需要有人在表格里「添加文档应用」并给「可管理」。

**用应用身份建出来的表，人是看不到的。** 用 `tenant_access_token` 创建或复制的多维表格，所有者是应用本身。必须转移所有者，或者把人加成协作者。

**转移所有者时要给应用留权限。** `transfer_owner` 接口带上 `old_owner_perm=full_access`，否则转完之后应用自己就没法再读写这张表了。转移可能因为对方的权限设置失败，要准备退路（加成可管理协作者）。

**手动复制的表是全新的。** 人在界面上复制一张表，得到的是新的 `app_token`，不继承协作者，应用没有权限。想让程序接管副本，要么由程序来复制，要么让人在副本里重新添加文档应用。

## 复制多维表格

**`without_content=true` 不会带自动化和仪表盘。** 只复制结构的话，自动化流程和仪表盘都丢了。想要完整的副本，必须带内容复制，然后自己把数据行删掉。

**接口复制出来的自动化全部是停用状态。** 不管母版里开没开，副本里一律是关的。需要读母版每条自动化的开关，再对副本里同名的逐条调 `PUT /workflows/{id}` 设成 `Enable`。

**清数据要在启用自动化之前做。** 利用上一条：副本刚复制出来时自动化都是关的，这时删示例行不会触发任何流程。先启用再删，删行就可能触发流程。

**副本里字段 ID 不变，数据表 ID 会变。** 所以在副本里定位数据表要按表名找，定位列可以直接用母版的字段 ID。

**副本刚建好时别急着读。** 复制接口返回后立刻去读表和字段，稳妥起见要准备好等几秒重试。

**母版和副本从此各自独立。** 母版后来的改动不会同步过去，没有「模板更新」这回事。

## 读写记录

**文本列读出来是数组，写进去是字符串。** 读到的是 `[{"text": "...", "type": "text"}]`，写的时候直接给字符串。

**公式列和引用列读出来多包了一层。** 是 `{"type": 2, "value": [10]}` 这种结构，要取 `value[0]`；人员类型的引用列 `value` 本身就是人员列表。

**按字段 ID 记列，不要按列名。** 读写记录的接口用的是列名，但使用者随时可能改列名。稳妥的做法是配置里记字段 ID，每次调用前把 ID 换成此刻的列名（缓存几分钟）。这样改名、调顺序都不影响。删列和改单选项的名字仍然会影响。

**写一个不存在的列名，整次更新都失败。** 不是忽略那一列，而是整条记录都写不进去。如果此时这一行正处于「处理中」，它就卡住了。写之前先核对列是否存在。

**回写偶尔会遇到网关 502。** 不重试的话，行会停在中间状态。回写要带重试，另外定时把停在「处理中」太久的行放回队列。

**单选列有默认值会导致误触发。** 如果用「某个单选列被填了值」作为触发条件，而这一列设了默认值，那么每新增一行都会立刻触发。触发列不要设默认值。

**查询一次最多 500 条，要翻页。** 字段列表、数据表列表也一样有分页，列多的表别忘了。

## 附件

**下载附件要带凭证。** 记录里附件的 `url` 不能直接下，需要带 `Authorization` 头；也可以用 `file_token` 拼 `/drive/v1/medias/{file_token}/download`。

**上传附件分两步。** 先调 `/drive/v1/medias/upload_all`，`parent_type` 填 `bitable_file`，`parent_node` 填这张表的 `app_token`，拿到 `file_token`；再把 `[{"file_token": "..."}]` 写进附件列。

## 建表和建列

**数据表的第一列不能是人员类型。** 建表时第一列给人员列会报 `Unsupported field type`。第一列用文本。

**数字列的百分比格式很挑。** 普通数字列和公式列的百分比格式只认 `0.00%`，写 `0%` 或 `0.0%` 会报错。

**公式列可以用接口建，跨表引用有专门的写法。** 引用其它数据表的列写成 `bitable::$table[tblXXX].$field[fldYYY]`。

**新建的多维表格和数据表会自带内容。** 新建多维表格自带一张默认数据表，新建数据表可能自带几行空行，不想要的话自己删。

## 做不到的事

下面这些目前没法用接口完成，只能在界面上手动做：

- 调整列的顺序。
- 设置看板视图按哪一列分组、卡片上显示哪些字段。
- 创建仪表盘里的图表。
- 读取或修改用「AI 页面搭建」生成的页面。这类页面在仪表盘接口里查不到。

## 运行方式

**轮询比想象中够用。** 没有用事件订阅，就是每 20 秒按条件查一次每张表。接入 5 张表、最大的一张一千四百多行，这个规模下没有遇到频控问题；更大的规模没有验证过。前提是查询要带过滤条件，只取需要处理的行，不要每轮把整张表读回来。

**别让一张表堵住所有表。** 有人一次导入上千行并且都满足触发条件时，如果按表顺序处理完再走下一张，别的表会等很久。每张表每轮设个上限，轮流来。

**出错的表要降频。** 一张表被删了或者权限被收回，每轮都去试只会刷日志。连续失败若干轮后改成十分钟试一次，恢复后自动回到正常节奏。

**程序自己会改的状态和人写的配置要分开放。** 一开始把分发出去的表也追加进配置文件，结果是每次想手改配置都得先停服务，否则会被程序覆盖。后来拆成两个文件：配置文件只读，程序维护的状态单独存。
